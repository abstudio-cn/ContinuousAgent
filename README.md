# ContinuousAgent

**一个能连续干下去的本机智能体。**

多数 agent 是「一问一答的聊天框」：聊到上下文快满了，就把前面的对话压成一段摘要（或者干脆截断），然后接着聊。这像每隔半小时失忆一次、再读自己刚写的便利贴。

ContinuousAgent 走另一条路：**它不压缩上下文，它写工作记录。** 活干到哪一步、下一步做什么、踩过什么坑，都落在磁盘上的 Markdown 里；上下文窗口只是「手边这张台面」，台面只放正在处理的这一摊活，其余的在档案柜里，随时能翻。于是它可以一轮接一轮地跑、被中断后接着跑、进程重启后还能接着跑。

TypeScript 写就 · 零运行时依赖 · 只监听 `127.0.0.1` · Windows 原生 GUI 能力 · 一套浏览器 UI 管多会话

> 安装、43 个工具的清单、HTTP 接口、排错手册 → [`readme_for_agent.md`](./readme_for_agent.md)

## 一、可持续运行：它凭什么能一直干

长跑不是「上下文够长」，是三个前提同时成立：

| 前提 | 缺了会怎样 | 本项目怎么做的 |
| --- | --- | --- |
| 状态可见 | 每轮都得重新摸索「我在哪」 | 工作记录是一份固定六个二级标题的 Markdown 快照，**每轮从磁盘读出来**注入提示词（`agent.ts` 的 `buildRequestMessages`） |
| 记忆可留 | 上下文一满就真丢了 | 记录 / 笔记 / 技巧库全部落盘为**人可读**的 Markdown / JSON，不依赖模型「记得」 |
| 过程可续 | 中断或重启就得从头来 | 会话历史与时间线落 `history.json` / `timeline.json`，重启时 `loadHistory()` 读回 |

再加两道刹车，防止「一直跑」退化成「一直空转」：

- **完成标记**：模型自己确认全部做完才停（输出 `[[DONE]]` 即停止自动续跑），而不是跑满轮数才停。
- **重复调用熔断**：最近 30 次调用里，同一个「工具名 + 规范化参数」出现超过 10 次，本轮立即中断（`repeat-guard.ts`）。

默认就是长跑配置：`continuousMode: true`、`maxTurns: 500`（`src/server/settings.ts`）。会话之间互相隔离——每个会话有自己独立的工作记录与笔记，并行开会话不会串味。

## 二、不做上下文压缩，那做什么

### 2.1 先看看「压缩」通常指什么

| 常见做法 | 具体干了什么 | 代价 |
| --- | --- | --- |
| 摘要压缩 | 把旧对话喂给模型，生成一段摘要替换原文 | 多一次 LLM 调用；摘要会丢细节、会写错、会随轮次漂移；**每次改写都动历史前缀 → 提示词缓存持续失效** |
| 滑窗截断 | 只留最近 N 条，更早的直接删 | 删掉就是真丢了，模型甚至不知道自己忘了什么 |
| 向量检索 | 历史切块存向量库，按相似度召回 | 引入向量库依赖；召回不准时关键上下文拿不到；多一跳 IO |

三者共同的毛病是同一个：**「该记住什么」这件事被交给了黑盒**——摘要模型、相似度分数、或者一个写死的窗口大小。

本项目里搜不到任何摘要生成、向量嵌入或「把历史改写成短版本」的代码。`trimHistoryMessages` 只做一件事：按条数裁剪。

### 2.2 本项目的做法：台面 + 档案柜

**台面（上下文窗口）**：只放最近若干个**完整回合**（`historyMaxMessages` 默认 24）加首条需求。

裁剪点必须落在回合边界上（优先 `user` 消息处），`assistant.tool_calls` 与对应的 `tool` 结果**绝不拆散**——拆散了网关直接回 HTTP 400。移出台面的对话不是「被压缩了」，而是它本来就不必留在台面上。

**档案柜（磁盘）**：三层，各管一件事，绝不混用。

| 层 | 位置 | 写什么 | 更新方式 |
| --- | --- | --- | --- |
| 工作记录 | `<工作空间>\sessions\<会话ID>\work_state.md` | 当前任务状态：目标、进度、环境、已改文件、待办、风险 | **整份覆盖**，禁止追加流水 |
| 工作笔记 | 同目录 `work_notes.md` | 跨任务复用的稳定知识：命令、路径、坑与解法 | 追加 / 合并去重 |
| 全局技巧库 | `%APPDATA%\ContinuousAgent\global_tips.json` | 跨会话共享的**工具使用**技巧 | 按利用频次淘汰 |

关键设计：**工作记录是「当前状态快照」，不是「历史流水」**。它整份覆盖、只保留最新状态。于是它在上下文里占的空间是恒定的（不随轮数增长），而信息密度最高——每轮注入的都是「此刻该知道的」。

单条工具结果超过 20 000 字符会被截断（`llm.ts` 的 `MAX_TEXT_CHARS`），提示词里明确告诉模型「结果被截断、需要完整内容请重新读」。这也是同一个逻辑：台面上只放摘要长度，全量在文件里，随时能重读。

### 2.3 为什么这比摘要压缩更可靠

- **可审计**：记录是人可读的 Markdown。你可以直接打开看「它到底记住了什么、哪一步想错了」。摘要压缩你只能看一段模型写的散文。
- **可发现错误**：字段写错，人一眼看出来；摘要漂移了，几乎无法察觉。
- **不破坏缓存**：台面之上的前缀（系统提示词 2 485 + 工具清单 5 118 tokens）字节级稳定，提示词里刻意不放时间、PID、路径。真实会话 219 轮实测**缓存命中 88.5%**（见第五节）。摘要式压缩每轮都改写历史，命中率会一路下滑。
- **可恢复**：进程崩了重启，`loadHistory()` 加上重读工作记录，现场立刻回来。

### 2.4 代价（诚实说）

这套做法把负担从「压缩算法」转移到了「记录纪律」：**模型必须真的每轮更新工作记录**。否则台面一裁、档案柜是空的，长跑必然跑偏。

所以提示词把它写成强制项：六个必填二级标题、整份覆盖、写绝对路径与命令原文，验收标准是「一个不了解上下文的人只读这份记录，就该知道现在在哪、下一步做什么」。

换句话说：**它不假装记住了所有事，它把「该记什么」的判断交还给 Markdown 和你。**

## 三、仿照真人工作的方法

真人不靠「回忆」工作，靠「记录 + 复看 + 交接」。下面的对应关系不是比喻，每一条都落在具体文件和工具上：

| 真人的做法 | 对应机制 | 落在哪 |
| --- | --- | --- |
| 上班先翻交接班记录 | 每轮请求都把工作记录读出来注入 | `work_state.md` |
| 干完一件小事就更新进度 | `update_work_record` 整份覆盖 | 同上 |
| 长期经验记进笔记本，而不是写在便签上 | `append_work_notes` / `update_work_notes` | `work_notes.md` |
| 同事之间传方法，不传公司机密 | `global_tips`：写入自动脱敏，含项目信息会被拒绝 | `global_tips.json` |
| 桌面上只放正在处理的这一摊 | 上下文只保留最近完整回合 | 内存 |
| 不确定就先看现场，不凭印象 | 只读侦察：`read_file`、`screenshot`、`list_directory` | — |
| 改文件前先留底稿 | `changed_backup`：覆盖/替换前自动备份，可 `restore` | `<工作空间>\changed_backup` |
| 换班时说清「我干到哪了」 | 记录里的「当前进度 / 待办」两节就是交接内容 | `work_state.md` |
| 干完一件事打个勾收工 | `[[DONE]]` 停止自动续跑 + `rename_session` 收尾命名 | — |
| 原地转圈会被组长喊停 | 重复调用熔断 | `repeat-guard.ts` |
| 说话留证据，不空口说「我干完了」 | 每步留下可验证证据：退出码、stderr、读回内容 | — |

一句话：**让 agent 像人一样「先看、再动手、随手记、交班写清」，长跑才有意义**；否则跑得越久，它越像在梦游。

### 附：除了会记事，它还会动手

这是它和「只碰代码的 agent」的另一处差别——能力面是真的 GUI，不只是文件加 Shell：

| 维度 | 常见形态 | ContinuousAgent |
| --- | --- | --- |
| 能力边界 | 文件 + Shell + 网络 | 再加窗口枚举、截图、键鼠注入、Windows OCR、剪贴板、进程 |
| 观察界面 | 前台截图，会抢焦点、打断你正在干的事 | `screenshot_background` 只走 `PrintWindow`：不激活、不改前后台与叠放顺序，窗口被遮挡也能拿到它自己的画面 |
| 权限模型 | 要么全权、要么全否 | 默认只能写工作空间；越界读写要在对话里弹卡片批准，按会话持久化；插件工具逐次审计 |
| 发生错误 | 靠 git 或人工收拾 | 每次覆盖/替换前自动备份，可一键回滚 |
| 成本可见 | 只给一个总数 | 每轮输入拆成缓存命中 / 未命中两段计价，顶栏、卡片脚注、状态栏三处对账 |
| 依赖体量 | 几十上百个 npm 包 | `dependencies: {}`，运行时零依赖 |

## 四、运行效率（本机实测，可复现）

测法：`node scripts/bench.mjs --json`。冷启动用隔离端口加临时数据目录反复起停测得。数字来自本机（Node v26.12.1，Windows）。

| 项目 | 实测 | 说明 |
| --- | --- | --- |
| 冷启动到 API 就绪 | **257 ms** | 从启动命令到 `GET /api/state` 返回 200 |
| 常驻内存 | **62.1 MB** RSS / 13 线程 | 空载单进程，原生桥按需启动 |
| token 估算（0.7 MB payload） | **0.457 ms/次** | 每次请求前跑一次，17.6 万 token 的 payload 不到半毫秒 |
| Markdown 渲染（20 k 字符） | **0.12 ms/次** | 单条长文档一次性渲染 |
| 流式 100 步渲染 | **77.9 ms → 4.4 ms（17.7×）** | 旧做法每步全文重渲染；现为 `MarkdownStream` 只处理新增行 |
| 流式 200 个 delta 的 SSE 开销 | **7 个事件 / 1.2 KB** | 合并 `item_update`，不再每个 token 推一次 |
| 会话列表统计（5 会话 × 2 文件） | **0.484 ms/次** | `/api/state` 与会话广播都会调用，故做内存缓存 |

几处让它「快得起」的取舍：静态资源按请求 `stat` 加流式读盘，配 ETag 与 `Cache-Control: no-cache`（改完前端刷新即生效，不重启）；截图默认转 JPEG(60)、宽度上限 1280、只带最近 2 张；一次请求只精确估算一次 token，超预算才做二次收缩；单进程加行协议原生桥（`scripts/native-host.ps1` 常驻，stdin/stdout 传 JSON），比每次工具调用都新起一个 PowerShell 快一个数量级。

## 五、Token 花在哪，以及为什么「不压缩」反而更省

实测脚本：`npm run build && node scripts/token-report.mjs`（`--json` 机读，`--turns N` 改轮数）。它直接 import 编译产物里的真实实现来算，不是另写一份「假装跑」的模拟。

### 5.1 每轮固定开销 7 603 tokens

| 组成 | tokens |
| --- | --- |
| 静态系统提示词 | 2 485 |
| 工具清单（43 个工具的 JSON Schema） | 5 118 |
| **每轮都要发** | **7 603** |

这 7 603 是**字节级稳定**的——时间、PID、路径这些易变信息被挪到请求末尾的动态上下文，所以同一会话每一轮都能命中提示词缓存。它占单次请求峰值的 **66.5%**，而它恰好是**最便宜的那部分**（命中价通常是未命中的 1/10 量级）。

### 5.2 同一段会话，全量重发要贵 1.84 倍

模拟 40 轮持续托管（每轮 1 条带 3 次工具调用的 assistant + 3 条工具结果）：

| 做法 | 累计输入 | 单次请求峰值 |
| --- | --- | --- |
| 朴素实现：全量历史重发、工具结果不截断 | 825.1 k | 33.0 k |
| **本项目**：静态前缀 + 回合边界裁剪 + 单条工具结果截断 20 k + 只留 2 张图 | **447.9 k** | **11.4 k** |
| 比值 | **1.84×**（省 45.7%） | **2.9×** |

注意这里省下的**不是「压缩」省下的**，而是「不重复发送已经在磁盘上有副本的过程细节」省下的。台面裁掉的部分，档案柜里都有。

### 5.3 真实会话实测：命中 88.5%，输入:输出 95:1

本机 3 个真实会话、219 轮真实 LLM 调用聚合：

| 指标 | 实测值 |
| --- | --- |
| 累计输入 | 16 238 606 tokens |
| 其中命中提示词缓存 | 14 373 248 tokens（**88.5%**） |
| 平均每轮输入 | 74 149 tokens（命中 65 631 / 未命中 8 518） |
| 平均每轮输出 | 778 tokens |
| **输入 : 输出** | **95 : 1** |

这张表说明两件事：钱几乎全花在输入侧，所以优化点是「别重复发同样的东西」，而不是让回答变短；88.5% 的命中率意味着实际计费主要落在每轮那 8.5 k 的增量上——**而这一切的前提正是前缀稳定、历史不被摘要改写**。

### 5.4 一张截图值多少

同一张 1718×870 的窗口画面，两种带法：

| 做法 | 尺寸 | payload | 视觉 token（`w×h/750` 口径） | 在历史里 |
| --- | --- | --- | --- | --- |
| **本项目** JPEG(60)，宽上限 1280 | 1280×648 | 75.1 KB | ≈ 1 106 | 只保留最近 2 张 |
| 朴素做法 PNG 原尺寸 | 1718×870 | 204.4 KB | ≈ 1 993 | 每张都留在历史里 |

单张差 1.8 倍（token）/ 2.72 倍（字节），再乘上「只留 2 张」，长时间挂机跑 GUI 任务差距会持续放大。

> 口径说明：token 一律用项目自带的保守估算器（CJK 1 token/字、其余 4 字符/token），与各家分词器有偏差，因此只做**相对倍数**比较，不冒充账单数字；视觉 token 用行业常用的像素口径 `w×h/750` 作数量级参照。金额请以你填的单价乘以实际 usage 为准。

## 六、三十秒上手

路径里的 `%USERPROFILE%` 就是你的用户主目录（PowerShell 中写作 `$env:USERPROFILE`，两者等价）。

```powershell
cd "$env:USERPROFILE\Documents\ContinuousAgent"   # cmd.exe 写法：cd %USERPROFILE%\Documents\ContinuousAgent
npm install
npm run build
npm start                     # 默认 http://127.0.0.1:7800
```

1. 打开 <http://127.0.0.1:7800>，在「设置 → 接口与模型」填 OpenAI 兼容地址 / Key / 模型名；
2. 要操作界面就点顶部「目标窗口」选一个进程；
3. 写目标 → Enter → 它自己一轮轮推进，随时可中断，中断后从工作记录接着干。

一键脚本：`.\start.ps1`（构建 + 启动 + 打开浏览器，支持 `-Port 8080 -NoBuild`）。

**安全提示**：服务默认只监听 `127.0.0.1`，但它能在你的机器上移动鼠标、按键、读文件。**不要**直接暴露到公网；远程访问请走 SSH 隧道 / Tailscale，并设置 `CONTINUOUS_AGENT_TOKEN`。

- **品牌资产**：顶栏与 favicon 换成手绘 SVG 卡通灯泡（`public/assets/logo.svg` + `.brand .logo` 样式），单文件双用途。
- **重复调用熔断**（`src/server/repeat-guard.ts`）：同一「工具名 + 规范化参数」在最近 30 次调用里出现超过 10 次即中断本轮；参数按键名排序后比较，`{"a":1,"b":2}` 与 `{ "b": 2, "a": 1 }` 视为同一调用。

- **插件系统**（`src/server/plugins.ts`）：插件是**子进程**，核心从不 import 插件代码；清单必须写用途，每次调用弹审计卡片，允许 / 本会话允许 / 拒绝三态，审计落 `plugin_audit.jsonl`。
- **全局技巧库**（`src/server/tips.ts`）：跨会话共享的工具经验，写入自动脱敏、拒绝项目信息、按利用频次淘汰、注入有 6 000 字符预算。
- **成本统计**：输入拆成「缓存命中 / 未命中」两段分别计价，可填单价与货币符号；`runtime.json` 结构不变，旧会话自动兼容。
- **改动备份**：`write_file` 覆盖 / `edit_file` / `apply_patch` 前自动备份，`changed_backup` 可 `list` / `restore` / `clear`，任务结束只清本会话。
- **读取申请（严格模式）**：`strictReadMode` 打开后，工作空间外的读也要卡片授权，五个读入口统一拦截。
- **会话自动命名**：新建会话不再弹框问标题；模型在收尾前 `rename_session` 起名，服务端再用首行兜底。
- **`exec_command` 后台执行**：`background=true` / `wait_ms` 立即返回任务 ID，配 `exec_output`（增量输出）与 `exec_kill`（整树终止）。
- **客户端 Markdown 重写**：`renderMarkdown` + `MarkdownStream` 增量渲染，先转义再生成 HTML，支持表格 / 任务列表 / 嵌套列表 / 代码块复制，流式输出与一次性渲染逐字符一致。
- **完成标记**：服务端不再生成「收到完成标记」这类文案，历史旧文案在渲染层剥离（不改写磁盘数据）。

## 九、边界与诚实声明

- **长跑的前提是记录写得好**。模型偷懒不更新工作记录时，这套机制的收益会明显下降——这是不做摘要压缩真实付出的代价，不是可以藏起来的细节。
- **不做反检测**：在线竞技游戏用自动化可能违反服务条款，能不能用请你自行判断合规性。
- **同一时间只允许一个会话运行**（多会话可共存、可切换，但并行跑会抢同一套键鼠）。
- **不能操作以管理员权限运行的窗口**（UIPI 限制，与桌面版一致）。
- **独占全屏 / GPU 合成窗口可能截不到图**，建议目标应用用无边框窗口；Windows OCR 依赖系统语言包，中文识别率一般，界面文案核对应以截图目视为准。
- 文中所有性能与 token 数字均为本机实测，脚本随仓库提供；换机器、换模型、换会话长度都会变，请以自己复现的结果为准。
