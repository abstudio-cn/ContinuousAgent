# 插件格式说明（示例）

插件是**纯配置 + 外部命令**：核心进程从不加载插件里的代码，只按 `plugin.json` 声明去启动子进程。
因此插件崩溃、死循环、乱打印都只影响它自己那一次调用的结果，不会影响 agent 核心。

## 安装方法

1. 在插件目录（设置面板「插件」分区里会显示完整路径，默认 `%APPDATA%\ContinuousAgent\plugins`）下新建一个子目录，比如 `sys-info`；
2. 把 `plugin.json` 放进去（可参考本目录）；
3. 设置面板 → 插件 → 勾选「启用插件」→ 点「重新扫描插件目录」。

## 字段说明

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 否（缺省用目录名） | 字母数字开头，只含字母数字 `_` `-`，≤32 字符 |
| `name` | 否 | 显示名 |
| `version` | 否 | 显示用版本号 |
| `purpose` | **是** | 插件用途。**没写用途的插件不会被加载**，因为审计界面必须能告诉用户「这插件要来干什么」 |
| `enabled` | 否 | `false` 时加载但不提供工具 |
| `tools[]` | 是 | 1~20 个工具 |

每个工具：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `name` | 是 | 工具名（字母数字下划线，1~40 字符），对外暴露为 `plugin__<插件id>__<name>` |
| `description` | 否 | 给模型看的说明 |
| `purpose` | 否 | 工具级用途，审计卡片优先展示它 |
| `parameters` | 否 | `{ 参数名: "说明" }` 或 `{ 参数名: {type, description} }` |
| `required` | 否 | 必填参数名数组 |
| `argv` | 二选一 | **推荐**：直接传给 spawn 的参数数组，不需要自己处理引号转义 |
| `command` | 二选一 | 交给 shell 的命令串；占位符会按 PowerShell / sh 规则加引号 |
| `timeoutMs` | 否 | 单次超时，1s~600s，缺省取设置里的值 |

占位符写在 `argv` 或 `command` 里：`{{参数名}}` 必填、`{{参数名?}}` 可缺省；另有内置的 `{{pluginDir}}`（插件目录绝对路径）。
**占位符必须先写进 `parameters`**，否则该插件会被判为加载失败（避免「静默替换成空」导致行为与声明不符）。

## 审计

插件工具每次被模型调用时，界面上都会出现一张审计卡片，展示：插件名与版本、**用途**、工具名、参数、即将执行的完整命令、插件目录，
并等用户点「允许本次 / 本会话允许 / 拒绝」。没有确认界面或 2 分钟未确认时一律拒绝执行；审计结果写入
`<数据目录>\plugin_audit.jsonl`（一行一次调用）。这个审计是强制的，没有开关可以跳过。
